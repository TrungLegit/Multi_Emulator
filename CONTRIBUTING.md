# Contributing to Multi_Emulator

Thank you for your interest in contributing to **Multi_Emulator**! This project is designed for educational purposes, and community contributions are greatly appreciated.

## How to Contribute

### Reporting Bugs

Before creating a bug report, please check existing issues to avoid duplicates. When submitting an issue, include:
- A clear and descriptive title
- Steps to reproduce the behavior
- Expected vs. actual behavior
- Environment details (OS, Python version, Node.js version, browser)

### Suggesting Enhancements

Enhancement suggestions are tracked as GitHub issues. Provide:
- A clear summary of the proposed feature or ADR improvement
- Use cases and educational value

### Pull Request Process

1. **Fork** the repository and clone your fork locally.
2. **Create a branch** for your feature or bugfix:
   ```bash
   git checkout -b feat/your-feature-name
   ```
3. **Install dependencies**:
   - Python: `pip install -r requirements.txt`
   - Node.js: `npm install`
4. **Make your changes** following consistent formatting across Python, Node.js, and HTML files.
5. **Test your changes** before committing.
6. **Commit** with a clear, descriptive message:
   ```bash
   git commit -m "feat: add description of change"
   ```
7. **Push** to your fork and open a **Pull Request** against the `main` branch.

## Code of Conduct

Please note that this project is released with a [Contributor Code of Conduct](CODE_OF_CONDUCT.md). By participating in this project you agree to abide by its terms.
